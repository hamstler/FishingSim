# FishingSim

Original RF4-style fishing simulator, Godot 4.3 .NET (C#). Polish README in README.md.

## Working rules (from the user: RF4-level visual upgrade)
- Goal: raise the visuals towards Russian Fishing 4 while keeping every game mechanic and the architecture. Godot 4.3 .NET, C# only (never GDScript), Forward+, shaders as native .gdshader files (rendering effects in shaders, not C#), PC.
- Work in independent stages. Before modifying: inspect the existing implementation, list the files to change, explain the strategy. After each stage: dotnet build, report errors, modified files, visual changes (screenshots: never claim a visual result from a successful build alone), performance where measurable (lavapipe cannot: ask for F11 numbers). Do not start the next major stage without the user's approval.
- Validation after changes: build, scenes, shader compilation, resource references, run the game (screenshot tool), existing gameplay (test suites), visual benchmarks.
- Never create duplicate systems, never delete functionality, preserve classes, namespaces, scene node paths and signal connections. The roles the user names map onto existing classes (extend these, do not add parallel ones): WaterController = World/Water.cs + shaders/water.gdshader; LightingController and SkyController = World/SkyController.cs (sun, moon, environment, exposure by time of day; split out only with approval); WeatherController = World/WorldState (weather, wind, barometer, murk) + SkyController's rain/clouds; VegetationManager = World/Scenery (+ Graphics/GrassField, TreeFactory); FishingRodController = Fishing/FishingRod + RodRig; ReelController = the reel in RodRig (SetCrank, rotor, drag in FishingRod); FishingLineController = FishingRod.UpdateLine + Core/Physics/LineRope; GraphicsSettings = Graphics/GraphicsQuality + UI/GraphicsPanel; PerformanceMonitor = UI/PerfOverlay + Graphics/Perf + UI/FpsCounter.
- C#: strongly typed, [Export] for tunables on nodes, Godot signals where a node-to-node signal fits (the code base mostly uses C# events: keep them), no allocations or GetNode lookups in per-frame code (cache references), physics in _PhysicsProcess.

## Architecture
Pure logic in src/Core (injected IRng); data as .tres resources; saves via System.Text.Json.Nodes; shaders in shaders/.

## Art direction
- One look only: Nordic (Valheim-like). Native resolution in the root viewport, crisp procedural textures, volumetric fog with sun shafts, AO, bloom, teal-shadow/warm-light grade (GraphicsQuality.ApplyNordic), moonlit ambient at night (SkyController). Pixel art was removed.
- Textures (everything but the fish): 4096 px per 2 m tile (ground, bark, buildings; leaf atlas 4096 with 2048 cells, needles 2048, fern 1024x4096), painted on worker threads (GroundTextures records strokes and paints them in 32 parallel bands; designs are in 1024-px units scaled by K) and block compressed by the game itself (Graphics/BlockCompress: BC1 colour, BC3 colour+alpha, BC5 normal RG: Godot's compressors exist only in the editor), cached zstd-compressed in user://texcache/*.fstx (Graphics/TextureStore; bump the owner's CacheVersion/LeafVersion when a design changes; stale versions and old PNGs are deleted). Menu starts painting them in the background (GroundTextures/Textures/ProceduralTextures Prewarm*); headless runs skip them. Trilinear anisotropic filtering (BuildingFactory.Pixel). Window starts maximised, canvas_items stretch over a 1920x1080 base (stretch scale 1.5 keeps the old layout units), 3D at native resolution, fonts antialiased (no pixel look anywhere), anisotropic 16x and mipmap bias -0.5. Fish skins: src/Graphics/FishSkin paints them per pixel on worker threads (512×256 for fish in the lake, 4096×2048 + normal map for hooked/held/atlas fish via FishModel.Create(..., detailed: true)); screenshot mode 20 = skin sheet, 19 = atlas. ## Game rules worth knowing
- Tackle (data/tackle/*, lists in TackleLoadout and GearCatalog): RodKind/LineKind/BaitKind; TackleSlot.Leader ("brak" always owned) limits LineStrength and replaces line visibility; LineData.Stretch adds to rod shock absorption, braid +10% hook-set; BaitData.AffinityAs/AffinityScale resolve via species' family keys (spinner/spoon/wobbler/softbait/fly, written into data/fish) when a species has no entry of its own (FishSpecies.AffinityFor, BaitFamilies); lures (Reusable) are not used per bite, are lost with the hook, and the bite timer runs only while reeling; FishSpecies.BiteOff = per-second chance to bite through a non-wire leader; accessories Waders (LakeBed.WadeLimit), HookHone, ReelGrease.
- Methods (src/Core/Methods/FishingMethods.cs, pure, tested in the core suite; FishingRod.CastMethod fixed at the cast): Method.For(rod kind, bait kind): a lure = Spinning on any rod (LureRodMatch: spinning rod 1.25, else 0.85), bait on Bottom/Carp rods = Bottom, else Float; HookWindow 0.9 / 1.8 / 1.2 s. Spinning: LureMotion per LureFamily (bait.AffinityAs: spinner/spoon/wobbler/softbait/fly; LureSpec sink rate, run depth slow/fast, ideal speed range, snag rate, still pace, twitch dart): depth by retrieve (FishingRod: normal = reel speed x0.3, Shift x0.6), BitePace (quality, falling jig, lift bonus after a fall, twitch flash) drives the bite clock x2 x LureRodMatch; RMB in Waiting = JerkLure (twitch, or jerk a snag: 35 % free, 8 % break), LMB on a snag pulls (12 %/s free, breaks after 4 s -> BreakLine(Hook)); SelfHookChance(aggression, reeling) starts the fight at the knock; the nibble is one knock and RMB at it strikes. The rod holds the Bobber (frozen) where the lure runs (_rigPos, depth) or the feeder lies. Bottom: the feeder takes one bait as groundbait when >= 2 (Cast), sinks 1.6 m/s, feeds GroundbaitSpots (5 m radius, strength cap 3, FadeHours 1.5 via World.Hour deltas, cleared on map change; PaceFor up to 2.75x; fish attraction scaled too); nibble = quiver plucks (Twitch 0.45), bite = _bitePull bends the tip; LMB drags the rig slowly. Bobber.SetTerminal shows the float (distance-scaled), the lure (built per family: spinner blade spin, spoon roll, wobbler rock, jig tail wag by LureSpeed, facing Heading) or the feeder; TerminalVisible = false in the fight for lure/feeder. RodRig.SetQuiverTip (bottom/carp rods: last two sections bright orange). ## Known issues
- The first start bakes the 4K photo sets: TextureStore.Get disposes its intermediate Images and Collect()s after every picture >= 2048 (native pixels otherwise wait for finalisation: the menu peaked at 3.9 GB); dispose Images you only bake. Unhandled .NET exceptions are written to user://logs/crash.txt (CrashLog, installed by the menu); Godot's own log is user://logs/godot.log. CrashLog keeps user://running.flag while the game runs; found at start (the last run crashed), it deletes user://shader_cache and user://vulkan (a crash mid-write left "Malformed smolv" caches that crashed every start). A user's RTX 3080 crashed (signal 11) after glslang failed on a valid built-in shader and RIDs came back null: memory exhaustion; 4K was moved to Ultra, then back to High at the user's request (lower the Textures setting if crashes return).
- Intermittent exit 134 when running several suites in one process.
- Main-thread costs cut after a user's F11 (i9-14900K, RTX 3080: game code 13.4 ms, 52 busy pool threads): GrassField places its clumps on a worker thread with its own LakeBed (Compute, pure; Apply on the main thread; one build at a time); FishAsset prepares a model off the main thread (Prepare: pictures decoded and compressed, meshes read straight from GLTFState as ImporterMesh (GenerateScene made GPU meshes, on the worker, without LODs), LODs generated, a foreign model joined, turned and given tangents) and Build only uploads; ArmIK caches the finger bones' rest bases/positions and reuses a finger search while the obstacles keep their place in the hand (0.5 mm); FirstPersonBody.BarGrip searches every way round the bar only every 12 frames, else 7 turn steps round the last best on the same side; FishingRod paints the 4096 px close-up skin (FishSkin.Prewarm, every core) at a nibble only for a species without a model (FishAsset.HasModel), else FishAsset.Prefetch.
